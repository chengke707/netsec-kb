# 第1章 网络安全概述

> 结构：1.1 基础知识 → 1.2 威胁因素 → 1.3 分类 → 1.4 解决方案 → 1.5 风险管理与评估 → 1.6 TCP/IP 安全 → 1.7 小结

## 1.1 网络安全基础知识

### 1.1.1 网络安全的含义

**课本原文（P2）**
> 网络安全是指网络系统的硬件、软件及其中的数据受到保护，不因偶然的或者恶意的原因而遭到破坏、更改或窃取，系统连续、可靠、正常地运行，网络服务不中断。

- 本质：**网络上的信息安全**。广义上，凡是涉及网络信息的[[保密性]]、[[完整性]]、[[可用性]]、[[真实性]]和[[可控性]]的技术与理论都属于网络安全研究范围。
- 四个视角：用户（隐私/商业利益）、网络运营管理者（防病毒、非法存取、DoS）、安全保密部门（过滤有害信息）、社会教育（控制不健康内容）。
- 包含四层内容：① 运行系统安全 ② 网络上系统信息的安全 ③ 信息传播安全 ④ 信息内容安全（狭义"信息安全"）。
- 计算机网络安全含义（P3）：通过计算机、网络、密码技术和信息安全技术，保护公用通信网络中传输、交换和存储的信息的机密性、完整性和真实性，并对信息传播及内容进行控制；结构层次包括**物理安全、安全控制、安全服务**。

### 1.1.2 网络安全的特征

四大特征：[[保密性]]、[[完整性]]、[[可用性]]、[[可控性]]

| 特征 | 课本定义要点 | 直观记法 |
|---|---|---|
| 保密性 | 信息不泄露给非授权的用户、实体或过程 | 不被窃听、不被非法使用 |
| 完整性 | 数据未经授权不能被改变，传输/存储中不被修改、破坏、丢失 | 不被拦截、丢失、篡改 |
| 可用性 | 授权实体可访问并按需求使用 | 正常提供服务 |
| 可控性 | 能够对信息的传播及内容进行控制 | 能管住信息流 |

> 提示：拒绝服务、破坏网络正常运行属于对**可用性**的攻击。

### 1.1.3 网络安全的威胁

三类基本威胁：[[非授权访问]]（影响保密性/完整性）、[[信息泄露]]（影响保密性）、[[拒绝服务]]（影响可用性）。

### 1.1.4 网络安全的关键技术

7 项：主机安全技术、身份认证技术、访问控制技术、密码技术、防火墙技术、安全审计技术、安全管理技术。

### 1.1.5 网络安全策略

- 策略 = **总体策略**（战略方针、分配人力物力）+ **具体规则**（什么活动被允许/禁止）。
- 内容 4 方面：① 网络用户的安全责任 ② 系统管理员的安全责任 ③ 正确利用网络资源 ④ 检测到安全问题时的对策。
- 实施要点：策略要真正执行而非"给审查者看的纸"；责任分配到部门并投入人力物力监督；技术与管理人员都要参与。
- 实现网络安全的三保障（P5，页脚未印出页码，已核对确认）：
> 实现网络安全，不但靠先进的技术，而且得靠严格的安全管理、法律约束和安全教育。
- RFC 1281 文档：互联网用户与管理员的安全使用准则。

## 1.2 威胁网络安全的因素

### 1.2.1 威胁网络安全的主要因素（6 类）

1. **威胁的类型**：非授权访问、假冒合法用户、破坏数据完整性、干扰系统正常运行、病毒破坏、通信线路被窃听。
2. **操作系统的脆弱性**：程序动态连接与打补丁机制（病毒温床）、可远程创建进程、Daemon 拥有核心层同等权限、RPC 无口令入口。
3. **计算机系统的脆弱性**：D 级（DOS、Windows 98，无防护）、C2 级（UNIX、Windows Server 2019，仍有 root/Administrator 超级用户）、静态口令易被破解。
4. **协议安全的脆弱性**：TCP/IP、FTP、E-mail、NFS 等存在漏洞；1988 年 Robert Morris 的 GUESS 口令猜测程序（蠕虫）每年造成上亿美元损失。
5. **数据库管理系统（DBMS）的脆弱性**：建立在分级管理概念上，且必须与操作系统安全配套。
6. **人为因素**：缺少安全管理员、缺少技术规范与定期测试、口令长期处于默认状态。

### 1.2.2 各种外部威胁（5 类）

1. [[物理安全]]：偷窃、废物搜寻、间谍活动。
2. **网络威胁**：电子窃听（局域网广播式，网卡设为混杂模式 Promiscuous Mode）、冒名顶替。
3. [[身份鉴别]]：身份识别（出示证明）+ 身份认证（核查）；口令脆弱、口令圈套（伪装登录界面）、密码字典暴力破解。
4. **程序攻击**：计算机病毒（自我复制）、特洛伊木马、逻辑炸弹。
5. [[系统漏洞]]：逻辑设计缺陷或编写错误；陷阱（后门，如 VMS 维护账号、BIOS"万能密码"）；BSD TCP/IP 的 r 命令（rlogin、rsh）天生不安全。

### 1.2.3 防范措施（8 条）

① 用[[备份与镜像]]技术提高数据完整性 ② 防治病毒 ③ 安装补丁程序 ④ 提高物理安全 ⑤ 构筑[[防火墙]] ⑥ 仔细阅读日志 ⑦ [[加密]] ⑧ 提防虚假的安全（假补丁/假更新诱骗下载木马）。

> 防火墙不能防范内部攻击（只防卫网络边缘），也不能完全防范恶意代码（病毒、特洛伊木马）。

## 1.3 网络安全分类

- 计算机安全 3 类：**实体安全**（环境、设备、媒体安全）、**网络信息安全**（网络畅通准确 + 网上信息安全）、**应用安全**（程序开发运行、I/O、数据库）。
- 网络信息安全 4 类：
  1. **基本安全类**：访问控制、授权、[[认证]]、[[加密]]、内容安全（访问控制是隔离的基本机制）。
  2. **管理与记账类**：安全策略管理、实时监控、报警、集中管理与记账。
  3. **网络互联设备安全类**：路由器、通信服务器、交换机的安全管理。
  4. **连接控制类**：负载平衡、可靠性、流量管理。

## 1.4 网络安全问题解决方案

### 1.4.1 网络信息安全模型（图 1-1，金字塔）

自底向上 5 层：**政策、法律法规 → 增强的用户认证 → 授权 → 加密 → 审计与监控**

![[配图/图1-1-网络信息安全模型.png]]

- 政策法律法规是**安全基石**（建立安全管理标准）。
- 增强的用户认证是**技术措施的首道防线**，目的是提供访问控制。认证 3 种方法：① 用户持有的凭证（钥匙、门卡）② 用户知道的信息（密码）③ 用户独有的特征（指纹、声音、视网膜）。
- [[授权]]：为特许用户提供合适访问权限，并监控活动使其不越权。
- [[加密]] 满足 4 需求：认证、一致性（不被篡改）、隐秘性（不被非法查看）、不可抵赖（接收者无法否认收到）。
- **审计与监控**是系统安全的**最后一道防线**，含数据备份，可问题再现、责任追查、数据恢复。

### 1.4.2 安全策略设计依据

- 核心原则（最重要的决策）：
> 准许访问除明确拒绝以外的全部服务程序，或拒绝访问除明确准许以外的全部服务程序。
- 其他考虑：内部/外部用户分别提供哪些服务、初始与后续投资、方便程度与服务效率、**复杂程度与安全程度的平衡**（安全系统越复杂越容易遭破坏）、网络性能。

### 1.4.3 具体的网络安全问题解决方案

1. [[信息包筛选]]：常驻路由器/专用主机的规则数据库，逐包审查。

   ![[配图/图1-2-信息包筛选位置.png]]

2. [[应用中继器]]：每项服务装于最终主机与网关（堡垒主机），隐藏内网拓扑。

   ![[配图/图1-3-应用中继器配置.png]]
3. **保密与确认**：保密 = 只有预定接收者能阅读解释；确认 = 向接收者保证发送者身份且传输中不被修改。

**安全方案由简到繁（图 1-4 ~ 1-7）**：

![[配图/图1-6-双路由器安全系统.png]]　![[配图/图1-7-高级安全系统.png]]

> [[DMZ]]（非军事区）：设置堡垒主机的有用位置，存放允许公用网络用户访问而又不危及内网安全的信息或服务。

### 1.4.4 网络安全措施

- 完整网络安全系统至少 3 方面：① 法律法规及规章制度 + 安全教育 ② 技术措施（防毒、加密、授权、认证、防火墙）③ 审计和管理措施（实时监控、实时改策略、漏洞检查）。
- 常用方法 10 条：修补漏洞、病毒检查、加密、身份鉴别、防火墙、捕捉闯入者、直接安全守则、空闲主机守则、废品处理守则、口令守则。
- 额外措施：选容错服务器、服务器备份（冷备份/热备份，热备份实时性好被广泛采用）、网络设备与通信线路备份。

### 1.4.5 互联网安全管理

- 背景：TCP/IP 先天弱点（IP 地址空间不足、安全性能差、网络管理机制薄弱），互联网更易被攻击。
- 保密基本原则：① 根据安全问题定策略 ② 新技术的出现及时补充策略 ③ 内网 Intranet 与 Internet 之间设防火墙，IP 地址分配可用**双轨制**。
- 管理功能：立法规范、加强审计跟踪、建立规章制度（许可证制度、操作规范、安全责任制）。
- 加大安全技术开发：加密、鉴别、密钥管理、访问控制、安全审计标准化研究。

### 1.4.6 网络安全的评估

- 安全措施 3 目标：① 对存取的控制 ② 保持系统和数据的完整 ③ 能恢复系统、备份数据。
- 评估前 9 问：有无安全方案、方案审查、相关人员、技术保障、网络类型、联网影响、接入方式、可访问用户、是否需要加密。
- 可请第三方（网络安全评估机构/专家）评估；先制定细致方案再投入。

## 1.5 网络安全风险管理及评估

### 1.5.1 网络安全风险管理

> 网络安全风险管理指的是识别、评估和控制网络系统安全风险的总过程，它贯穿整个系统开发的生命周期，其过程可以分为风险评估与风险消除两个部分。

- 主要步骤：**确定风险管理的范围和边界 → 建立安全风险管理方针 → 建立风险评估准则 → 实施风险评估及风险处置**。
- 范围与边界：业务范围、物理范围、资产（软件/物理/数据/人员/服务）、技术范围。
- **风险处置 4 种方式：降低风险、避免风险、转移风险、接受风险**；处置要平衡损失与成本。

### 1.5.2 网络安全风险评估

> 网络安全风险评估就是对网络自身存在的脆弱性状况、外界环境导致网络安全事件发生的可能性以及可能造成的影响进行评估。

- 关键技术：[[网络扫描]]技术（实时监控、主动检测）、网络漏洞扫描（端口扫描对比漏洞库 / 模拟攻击获取漏洞信息）。
- 指标体系原则：**动态性、科学性、可比性、综合性、可操作性**。
- 国际流行标准：ISO/IEC 13335（IT 安全管理指南）、BS 7799-1（信息安全管理体系）、AS/NZS 4360（风险管理标准）。
- 流程：① 识别威胁和判断概率 ② 测量风险（定性/定量）③ 风险分析结果（定量法：金钱损失量；定性法：高/中/低或 1~10 级）。

### 1.5.3 网络安全工程

- 四步：安全检测与评估 → 制定安全目标 → 网络安全实施 → 人员培训。
- 安全目标 3 项：**完整性、可靠性**（可信度：完整性+准确性+发送人身份验证）、**可用性**。
- 实现安全目标 5 个方面：网络攻击实时分析和响应、网络误操作分析和响应、安全漏洞分析和响应、配置分析和响应、风险形势的分析和响应。
- 网络安全实施 4 维度：**传输安全**（端到端加密，链路加密机）、**网络安全**（系统安全、防攻击系统、防病毒系统）、**内部信息安全**（CA 认证中心 + 主机防护系统）、**安全管理**（统一管理、文档系统、管理机构）。
- 人员培训：
> 在网络安全的各种因素中，人员是最根本、最重要的。

## 1.6 TCP/IP体系的安全策略

### 1.6.1 TCP/IP 体系的安全

**课本原文（P25）**
> TCP/IP 作为当前最流行的协议之一，却并未在设计时考虑到未来的安全需要，因此协议中有诸多安全问题。

- **已存在的安全漏洞**：
  1. 数据链路层：CSMA/CD 共享信道，任何帧到达同网段所有接口 → 可在线窃听。
  2. 网络层：ICMP Echo（ping）可淹没服务器；可建立秘密通道开后门。
  3. IP 漏洞：源 IP 地址发送后几乎不用 → **IP 欺骗**（伪装成被信任主机）。
- **各层安全**：
  - 物理层：网络接口层对应 OSI 物理层+数据链路层；措施少，最好用"隔离技术"，加强实体安全管理。
  - 网络层：IPv4 无安全特性；**网络分段**（物理分段/逻辑分段）+ [[VLAN]]（广播变点到点，防范监听）。
  - 传输层：SSL/TLS（Netscape 设计）——**SSL 握手协议**（交换版本、算法、身份认证、密钥）+ **SSL 记录协议**（分段、压缩、数据认证、加密）；支持 Diffie-Hellman、RSA、MD5、SHA、RC4、DES。
  - 应用层：最灵活的安全服务层。方案：① 逐应用修改（如 PEM，依赖 PKI；PGP 用分布式信任模型）② S-HTTP（文件级安全）③ 电子商务安全交易（SET 协议，支持 X.509 证书）。

### 1.6.2 ARP安全

- [[ARP安全]]定义：通过 ARP 严格学习、动态 ARP 检测、ARP 表项保护、ARP 报文速率限制等措施保证网络设备安全性。
- **5 种攻击**：ARP 泛洪、ARP 欺骗主机、欺骗网关、中间人攻击、IP 地址冲突。
- **ARP 欺骗原理（图 1-8）**：攻击者冒充网关/主机发送虚假 ARP 应答（含网关 IP + 自己 MAC），主机和网关更新 ARP 表后，两者间流量都经攻击者转发。

![[配图/图1-8-ARP欺骗原理.png]]
- **防范 6 条**：DHCP 绑定 IP+MAC、静态 ARP 映射表、ARP 缓存超时设置、架设 ARP 服务器、主动查询（定期核对 IP-MAC 对应）、防火墙连续监控。

### 1.6.3 DHCP安全

- DHCP：动态分配 IP、子网掩码、默认网关等参数，减少地址浪费与冲突。
- **3 种攻击**：DHCP 服务器欺骗（无认证机制，仿冒者先回应分配错误地址）、DHCP 泛洪、中间人攻击（双向仿冒，报文"二手"中转）。
- **防护**：硬件防护（交换机端口 MAC 动态绑定）、网络防护（除合法 DHCP 服务器接口外禁止发送 DHCP Offer 包）。

### 1.6.4 TCP安全

- TCP：**面向连接、可靠、基于字节流的传输层通信协议**；3 次握手建立、4 次挥手断开。
- **6 类攻击**：
  - [[TCP SYN 泛洪攻击]]：伪造大量 SYN 请求不回应 ACK，耗尽资源 → DoS；防御：防火墙、**SYN Cookie**、限制连接数。

    ![[配图/图1-9-TCP-SYN泛洪.png]]

  - TCP SYN 扫描：SYN→收到 SYN+ACK 即发 RST，无痕迹探测开放端口；防御：防火墙、关闭不常用服务、IDS/IPS。
  - TCP FIN 扫描：发 FIN 探测，闭合端口回 RST。
  - TCP LAND：源 IP = 目的 IP = 目标主机，自环死循环崩溃。

    ![[配图/图1-10-TCP-SYN扫描.png]]　![[配图/图1-11-TCP-FIN扫描.png]]　![[配图/图1-12-TCP-LAND.png]]

  - TCP 中间人：会话劫持（窃听获取序列号/确认号后伪造数据包冒充）+ 连接重置（伪造 RST 断开连接，对长连接有杀伤力）。

    ![[配图/图1-13-TCP中间人.png]]
  - TCP 连接重置攻击。
- 防御共性：防火墙过滤、SYN Cookie、限制连接数、关闭不常用服务、入侵检测/防御系统。

### 1.6.5 DNS安全

- DNS：TCP/IP 应用程序的分布式数据库，提供主机名↔IP 转换；通过 UDP 与 53 端口通信；有正/反向解析。
- **不安全因素**：UDP 本身不安全、树形结构易单点故障、BIND 软件存在缓冲区溢出/拒绝服务漏洞。
- **4 类攻击**：DDoS、缓冲区投毒（在 DNS 缓存中存入错误数据，重定向到错误 IP）、区域信息泄露（泄露网络拓扑/子网结构）、域名劫持（窃取账号密码取得域名管理权）。
- **防范**：包过滤防护（端口 53 / 合法 IP / 流量限制，正常请求 ≤512 字节）、防火墙保护（Split DNS 内外分离）、网络拓扑限制（避免同一子网/链路/路由器/自治域/物理位置）、DDoS 防范（IDS、多数据中心冗余、防火墙限流、流量分析）。
